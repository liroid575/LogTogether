# LogTogether v0.11.1 — Social reliability & testing polish

This release focuses on making the v0.11 social features reliable enough for real family testing while improving workout/circuit ergonomics.

## Rest timer reliability

- Rest completion now uses a preloaded normal audio asset plus the Web Audio fallback.
- Where supported, the app requests a playback audio session so iPhone/iPad playback has a better chance of being audible in silent-mode scenarios.
- Rest completion also requests a short vibration pattern on browsers that support the Vibration API and flashes the workout UI as a visual fallback.
- Device/OS silent, vibration and Focus/Do Not Disturb policies remain authoritative; the PWA cannot override them.

## Notification reliability

- Gold Day, Badge and Poke in-app notification preferences are switched on once for existing users during the v0.11.1 preference migration. After that migration, user choices are respected normally.
- Devices that already granted notification permission can automatically restore their push subscription. Devices that have not decided yet get an explicit Enable notifications prompt; browser permission can never be granted silently.
- Notification payloads now use descriptive titles/bodies and stable event tags.
- Gold Day social delivery is based on a daily idempotent event, so deleting/re-adding activity cannot create multiple Gold notifications or multiple earned Pokes for the same person/day.

## Pokes and abuse controls

- Normal members can store up to 7 Pokes.
- Recipients can mute Pokes from an individual person or an entire group.
- The server keeps the existing sender/recipient cooldown and adds a recipient-wide rolling flood limit.
- Blocked or rate-limited attempts do not consume the sender's Poke.
- The family owner has temporary unlimited Pokes for testing, but recipient mute and flood protections still apply.
- Owner-only diagnostics include a self test-notification action.

## Quick Guide and circuit UI

- Quick Guide is taller, uses larger mobile text, and uses a native horizontal scroll track instead of abrupt page replacement.
- A new Poke tutorial page explains earning, the 7-Poke cap, emoji Pokes, cooldowns and mute controls.
- Circuit builder movements are visually separated, explicitly labelled Movement 1 / Movement 2 / …, and the movement marker is moved to the top-left.
- The Rounds field now explains that one round means completing every listed movement in order.

## Workout timing

- Rep-based strength and mobility sets can optionally define a target `Work s` time as well as rest time.
- The active workout timer counts down toward that target and then shows overtime while actual elapsed duration remains recorded.
- The field is optional and does not alter science scoring or progression logic.

## Developer diagnostics

- Active family owners get a collapsed **Developer · Cloud usage** section under Data, backup & diagnostics.
- It reports LogTogether-owned backend counters such as social events, push deliveries/failures and Poke blocks, plus a test-notification button.
- These counters are explicitly not an official Firebase/Google Cloud bill; authoritative TWD charges remain in Google Cloud Billing.

## Infrastructure and compatibility

- Gold Day social triggering moves from the weekly aggregate trigger to `familyProgress` daily Gold state.
- Server-managed social-event, Poke flood-limit and developer-usage documents are denied to clients by Firestore rules.
- Existing v0.11.0 VAPID keys remain reusable so current push subscriptions do not need new keys.
- AppState remains schema v1 with additive optional fields.
