# v0.14.0 — Exercise schema, builders, and timer consistency

## Exercise and timer behavior

- The empty Sports / Other group is no longer rendered. Its legacy type remains readable in old data.
- One shared laterality resolver now controls live workouts, circuits, completed-activity logging, and saved-routine editing. Downward-facing Dog is bilateral and no longer shows Left / Right / Both.
- Static stretches start with two 30-second holds and a 15-second transition. Hold time counts down from the configured duration. A positive recovery counts down; zero means no recovery timer.
- The existing safety and scoring rules are unchanged. Stretch duration continues to contribute to mobility time without granting intensity bonuses.
- The full 156-exercise review, proposed defaults, device metrics, product decisions, and sources are in `docs/research/LogTogether_v0.14.0_exercise_and_ux_audit.xlsx`.

## Workout and routine experience

- A Workout / Circuit selector shows only the chosen builder on an empty live workout.
- Saved routines remain choose-first. The editor numbers and separates movements, groups the exercise picker by library section, places deletion near the selected routine, and supports drag reorder with Up / Down controls as an accessible fallback.
- Circuit movements and unstarted standard-workout movements support the same reorder pattern.
- Home adds an Edit action beside Saved routines and opens the manager without selecting a routine automatically.

## Missions and History

- Chosen Activity accepts up to two activities. Either selected activity can count once on a calendar day, so two activities on the same day never duplicate progress.
- Gym strength is available and requires at least four completed working resistance sets from Gym exercises on that day.
- Hiking, swimming, running, cycling, and kickboxing keep their existing activity-specific matching. Legacy Any Activity and Jump Rope values remain readable but are not selectable.
- History filters now describe recording method: All, Live sessions, and Logged activities. New records store `live`, `manual`, or `imported`; older records use a conservative timing-based fallback.
- Backfilled workouts use the History clock icon. Family recent workouts add a labelled divider when the date changes.

## Invite flow, privacy, and offline behavior

- An invite opened in a browser is retained locally for up to seven days so installing the PWA does not discard the pending join flow.
- The invite screen provides platform-specific Add to Home Screen guidance and uses the browser installation prompt when it is available. Installation still requires the user's browser approval.
- Invite tokens remain opaque, are removed after a successful claim, and Cloud access still requires the invited Google identity and Firestore authorization.
- No runtime dependency was added. Exact photos, GPX traces, hydration entries, supplement entries, height, and weight retain their existing privacy boundaries.

## Scientific basis

- General activity references follow WHO's adult guideline of 150–300 minutes of moderate aerobic activity or 75–150 minutes vigorous activity per week, plus muscle strengthening on at least two days.
- Static-stretch defaults stay within ACSM's commonly cited 10–30 second hold and 2–4 repetition range for most adults. The 15-second recovery is a UI transition default, not a clinical prescription.
- The Gym mission's four-set threshold is a transparent game rule for meaningful participation. It is not presented as a complete strength-training prescription.
- Sources and exercise-by-exercise decisions are recorded in the audit workbook rather than embedded as unsourced claims in the interface.

## Verification

- Production TypeScript build and unit tests cover exercise grouping, laterality, stretch defaults, two-choice activity missions, Gym qualification, recording-source filters, date dividers, reordering controls, invite persistence, and the zero-rest guard.
- Existing security tests continue to cover owner-scoped writes and family-readable shared data.
