# LogTogether v0.11.3 — Timer & Cloud sign-in reliability

This release is intentionally narrow and prioritizes two tester-blocking reliability issues.

## Workout timer cues

- Start = one short cue.
- Finish = one short cue.
- A configured work target reaching zero = two cues once, then overtime counts upward.
- A configured rest target reaching zero = two cues once, then overtime counts upward.
- Work timers with no target continue counting upward and never generate a deadline cue.
- Timer deadlines are timestamp-based, so returning from another app immediately restores the correct remaining/overtime time and emits a missed deadline cue once.
- iOS audio sessions use transient/mixing behavior where available so LogTogether does not deliberately take exclusive control from YouTube or music.
- The timer audio preload no longer plays a near-silent copy of the real cue on every Start/Finish action.

Mobile operating systems may suspend PWAs while fully backgrounded, so exact background-time audio remains best-effort. Timer state itself stays correct.

## Cloud sign-in

- Google popup results are consumed directly instead of waiting only on the global auth observer.
- Redirect fallback is explicitly completed on return with a visible "Finishing sign-in" state.
- Firebase Auth persistence uses IndexedDB -> localStorage -> sessionStorage fallbacks for restricted/private browser sessions.
- Invite codes survive a Google redirect within the current browser session.
- Firebase Auth now uses the deployed Hosting origin (`YOUR_AUTH_DOMAIN`) so redirect fallback is same-origin on browsers that block third-party storage.
- Failed/cancelled/network sign-ins now produce actionable UI states instead of silently returning to Local.
- Local workout data is still promoted/merged only after an active LogTogether Cloud membership has been verified.

## One-time OAuth setup

Before testing redirect fallback, the Google OAuth web client for `YOUR_PROJECT_ID` must authorize:

`https://YOUR_AUTH_DOMAIN/__/auth/handler`

Also ensure `YOUR_AUTH_DOMAIN` remains listed under Firebase Authentication -> Settings -> Authorized domains.

No Firestore rules, indexes, Cloud Functions, science scoring, or social-notification backend changes are required by v0.11.3.
