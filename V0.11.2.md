# LogTogether v0.11.2 — Notification onboarding & ordered workout flow

This release focuses on the reliability issues found during the first real v0.11 family tests. It keeps the v0.10 science model and v0.11 social model intact while making missed notifications recoverable, timer alerts easier to test, workout order unambiguous, and personal supplement logging more flexible.

## Timer alerts

- Replaced the primary rest/work completion media asset with a tiny compressed MP3 and keeps the existing Web Audio fallback, playback audio-session request, visual flash and supported vibration request.
- Audio is primed from workout interactions so later timer completion has an already-unlocked media element where the browser permits it.
- Added **Settings → Workout experience → Test timer alert** so each device can be checked without completing a workout.
- Device silent/Focus/vibration policy remains authoritative; a PWA cannot force iPhone vibration or override OS notification/audio policy.

## Social reliability and notification onboarding

- Pokes, Gold Days and badges are written to a small private per-user social inbox before Web Push delivery is attempted.
- A recipient with no push subscription can therefore still receive the event inside LogTogether the next time the updated app opens; lack of a push subscription no longer makes a Poke fail.
- The inbox is deliberately bounded to recent events and is readable only by its owner. Existing notification-category preferences, person/group Poke mutes, cooldowns and flood controls are still enforced server-side.
- Opening **Family** on a device without usable system notifications shows a playful 👋 ⭐ 💪 🏅 onboarding dialog with **Enable notifications**, **Not now**, and **Never show this reminder again**.
- Granted-but-missing push subscriptions are repaired automatically. Browser/OS notification permission is never bypassed.
- A suppressed Family reminder can be restored later from Settings.
- Foreground Pokes show a short rounded sender message plus a gentle ~4-second emoji rain; reduced-motion users receive the message without the rain.

## Quick Guide

- Keeps the taller/larger v0.11 guide, but restores a clear page-by-page feel with mandatory horizontal scroll snapping and `scroll-snap-stop: always`.
- Finger movement remains native while dragging, then settles on a complete guide page when released.

## Personal supplements

- Users can add exact personal supplement/product names alongside the built-in common catalog.
- Optional default amount/unit can be saved for a personal item.
- Custom text is stored exactly as entered: LogTogether does not translate it or infer product contents/dosage.
- Personal supplement catalog entries sync through the user's private preferences. Removing an item from the catalog does not rewrite historical supplement records because each historical entry retains its original custom label.
- Existing family-profile supplement sharing remains opt-in; exact custom names are shared only when that user has enabled the weekly supplement profile section.

## Authoritative workout and circuit order

- During an active workout, only the single next valid **Start** button is enabled.
- Normal workouts follow exercise/set order. Circuits follow Round 1 Movement 1 → Movement 2 → …, then Round 2 and so on.
- Future planned fields remain editable, but users cannot start a later set/movement before completing the current sequence.
- Older/out-of-order records remain renderable and an already-active set retains control of the flow.

## Circuit deletion safety

- **Remove round** now always uses the same full confirmation dialog as other destructive workout actions.
- The dialog explains that removing a round removes that round from every movement in the circuit.
- Single-movement removal continues to use the shared destructive confirmation pattern.

## Compatibility and cost

- AppState remains schema v1 with additive optional fields.
- Existing v0.11 VAPID keys, Firebase project, Functions architecture and push subscriptions remain compatible.
- No new paid service is introduced. The private social inbox adds only a small bounded number of Firestore documents per recipient and uses the existing v0.11 Functions/Firestore infrastructure.
